## Решения и инварианты

- Первая часть намеренно ограничена чтением: `RegistryVFS` всегда открывает ключи с `registry.READ`, а `MkDir`, `Remove`, `Rename`, `Create` и `SetAttributes` возвращают отказ в доступе даже при наличии прав записи у процесса.
- В URI используются `registry://` и URL-кодирование каждого имени. Это сохраняет имена, содержащие `/`, и не позволяет имени ключа внедрить дополнительный разделитель `\\`.
- Значение с пустым именем показывается как `(Default)` и при открытии снова сопоставляется с пустым именем Windows. При совпадении с одноимённым ключом приоритет имеет каталог.
- Текстовое содержимое значения — снимок на момент открытия. `REG_SZ` и `REG_EXPAND_SZ` не разворачиваются, числовые типы показываются в десятичном и шестнадцатеричном виде, остальные — в hex; это сохраняет тип и не выполняет данные реестра.
- Размер и `Revision` относятся к текстовому снимку, который получает просмотрщик, поэтому изменение типа или байтов значения меняет ревизию.
- В Wine/Posix-режиме Windows-пункт не добавляется: эта часть использует настоящий Windows Registry API и проверяется только Windows job-ами GitHub Actions.

## Проверка

Локальные сборки и тесты не запускаются по инструкции Лунобота. Выполняются только форматирование и `git diff --check`; компиляция и Windows-регрессии должны быть подтверждены GitHub Actions.
